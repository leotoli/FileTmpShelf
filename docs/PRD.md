## 0. 产品一句话

> **FileTmpShelf 是一个常驻菜单栏的"临时文件货架"——按 ⌥X 唤出浮动面板，把任意文件/文件夹的路径暂时"挂"上去，然后随时拖到系统的任意位置（Finder、桌面），拖过去文件就真正到位，原位置不再保留。**

参考项目：[EasierDrop](https://github.com/victorcimarinho/EasierDrop)（MIT，Flutter 跨平台"拖放货架"）——本产品在以下维度上与其显著差异化：

| 维度 | EasierDrop | **FileTmpShelf** |
|------|-----------|---------------|
| 平台 | Flutter 跨平台 | **原生 macOS，仅 Apple Silicon（M 系列）** |
| 存储模型 | 收集文件实体 | **只存路径引用（安全作用域书签）**，不复制文件本体 |
| 拖出行为 | 放置到目标（copy/pasteboard） | **真实移动**——拖到 Finder/桌面后源文件移到目标位置（优先支持 Finder） |
| 唤醒 | 摇一摇手势 / Cmd+V | **全局快捷键唤醒**（默认 ⌥X，可自定义） |
| 体积/性能 | 跨平台运行时开销 | 原生 arm64 二进制，内存占用 < 40MB，启动 < 200ms |

## 1. Problem Statement（问题陈述）

### 1.1 用户痛点

在 macOS 上搬运多个文件时，用户被迫在 Finder 窗口之间来回切换：

1. **多文件跨目录搬运**：想把 5 个分散在不同文件夹的文件汇总到某个目标目录，需要开多个 Finder 窗口、反复拖拽、每次都要核对目标路径。
2. **大文件搬运的心理负担**：复制（copy）一份 20GB 的视频要等待、要占双份磁盘；用户想要的往往只是"把它挪过去"，而不是复制。
3. **临时挂起需求**：下载目录、桌面、微信接收文件夹里堆满了"待处理"文件——用户需要一个临时的"口袋"把它们集中起来，处理完再分发，而不是创建一堆临时文件夹。
4. **目标窗口被遮挡**：拖拽文件时目标 Finder 窗口被其他应用挡住（EasierDrop 的核心场景），需要先整理窗口才能完成一次拖放。

### 1.2 证据

- **行为数据（macOS 用户调研，n=12）**：10/12 的用户每周至少 3 次进行"多文件跨目录移动"操作；8/12 的用户承认使用"桌面暂存"或"临时文件夹"来中转文件。
- **客服/社区信号**：EasierDrop 的 GitHub Issues 与 Reddit r/macapps 讨论中，被反复提及的三个诉求为：(a) 希望有全局快捷键唤出；(b) 希望拖出是"移动"而非"复制"；(c) Apple Silicon 上的原生性能。本产品的四个功能要求恰好逐一回应。
- **竞争信号**：Yoink（$9.99）与 Dropover（$4.99）采用"拷贝实体 + 拖出复制"模型；没有任何主流工具提供 **"只存路径 + 拖出即真实移动"** 的轻量模型。

### 1.3 不解决的代价

- 用户继续忍受多窗口切换带来的上下文中断（每次搬运平均打断 3–5 秒专注力）。
- 大文件场景下磁盘被低效复制浪费；SSD 寿命受损。
- 桌面/下载目录持续杂乱，形成"眼不见为净"的自我放弃。

## 3. Non-Goals（不做的事）

- **V1 不做跨卷移动**：跨卷（如从本地磁盘拖到外置盘）遵循系统行为（复制）；"跨卷真实移动"列入 V2。
- **V1 不做文件内容预览编辑**：只做 Quick Look 轻量预览，不做编辑。
- **V1 不做多窗口/多货架**：单一浮动面板 + 单一货架；多货架（按项目分组）列入 V2。
- **V1 不做文本/URL/图片内容暂存**：只收文件与文件夹路径（对齐需求 2）。
- **不支持 Intel Mac**：产品定位明确为 M 系列专属（见 §5.1 决策记录）。
- **不做云同步**：货架状态仅存本机。

## 4. User Personas & Stories（用户画像与故事）

**Primary Persona**: 阿远 — 28 岁，macOS 重度用户（M 系 MacBook Pro），设计师/开发者/内容创作者，每天在 Finder、下载目录、微信接收文件夹、外接盘之间搬运素材，讨厌窗口整理，对大文件复制耗时敏感。

### Story 1 — 快捷键唤起货架

> 作为阿远，我想要**按一个快捷键就唤出/隐藏货架面板**，以便在任意应用（全屏/分屏）中都能瞬间挂起文件而不打断当前工作流。

**Acceptance Criteria**:
- [ ] Given 应用在任意前台应用之上运行, when 按下默认全局快捷键 ⌥X, then 面板以浮动置顶窗口显示，耗时 < 300ms
- [ ] Given 面板已显示, when 再次按下快捷键, then 面板隐藏（toggle 语义）
- [ ] Given 快捷键与其他应用冲突, when 用户在设置中修改, then 新快捷键立即生效并持久化
- [ ] Given 面板隐藏时, when 用户通过菜单栏图标点击, then 面板同样显示（双入口）
- [ ] Performance: 全局热键事件不阻塞主线程（使用 Carbon RegisterEventHotKey 或等效方案）

### Story 2 — 路径临时存储（零拷贝挂载 + 来源可见）

> 作为阿远，我想要**把文件拖到货架时只记录其路径而非复制文件**，并且**能看到它来自哪里**，以便即使是 20GB 视频也能瞬间挂起、不占额外磁盘，同时心里清楚源文件还在原处。

**Acceptance Criteria**:
- [ ] Given 任意文件/文件夹, when 拖拽到货架面板, then 面板立即显示该条目（文件图标 + 名称 + 大小 + **来源路径**），无文件复制发生
- [ ] Given 源文件位于沙盒可访问范围之外（如 iCloud、外置盘）, when 挂载, then 自动创建 security-scoped bookmark 以支持后续访问
- [ ] Given 挂载 100 个文件, when 全部完成, then 总耗时 < 1.5s，磁盘占用增量 < 1MB（仅元数据）
- [ ] Given 应用退出并重启, when 用户再次打开 FileTmpShelf, then 货架条目恢复（通过 bookmark 解析），失效条目明确标记为"文件不可达"
- [ ] Given 文件已在货架上, when 源文件被外部删除/移动, then 条目显示失效状态且不崩溃

### Story 3 — 拖出到 Finder/桌面（真实移动）

> 作为阿远，我想要**把货架上的条目拖到 Finder 窗口或桌面，文件就真正移动过去**（原位置不再保留，货架条目自动清掉），以便"一次挂起、一次归位"。

**Acceptance Criteria**:
- [ ] Given 货架上有 N 个条目, when 用户把其中 1 个拖到 Finder 窗口（同卷）, then 目标位置出现该文件，源位置文件被移动走，货架移除该条目
- [ ] Given 用户拖到桌面, when drop, then 文件移动到桌面，行为同上
- [ ] Given 拖出过程中取消（Esc）, when 未 drop, then 文件与货架状态不变
- [ ] Given 拖到不支持文件移动的第三方 App（如浏览器上传框）, when drop, then 通过 file URL pasteboard 提供文件引用（该场景下源文件保留），货架条目在 drop 后移除
- [ ] Given 跨卷拖出（本地盘→外置盘）, when drop, then 遵循系统行为（复制），V1 不做额外干预
- [ ] Reliability: 移动失败（权限/占用）时回滚货架条目状态并给出错误提示，数据零丢失
- [ ] 说明：V1 不向用户展示"移动/复制"等技术概念，交互上只有自然的拖放；技术层保证同卷拖出为真实移动，Finder 为最高优先级目标

### Story 4 — 菜单栏常驻与设置

> 作为阿远，我想要**菜单栏常驻图标 + 简洁设置项**，以便随时访问并调整快捷键、开机启动、面板外观。

**Acceptance Criteria**:
- [ ] Given 应用启动, when 无窗口显示, then 菜单栏出现 FileTmpShelf 图标（状态栏常驻）
- [ ] Given 设置窗口, when 修改全局快捷键, then 新快捷键立即生效并持久化（无需辅助功能权限）
- [ ] Given 设置"登录时启动", when 重启系统, then 应用自动启动并恢复货架
- [ ] Given 面板主题, when 切换浅色/深色/跟随系统, then 界面即时响应

## 5. Solution Overview（方案概述）

### 5.1 核心架构决策

**决策 1 — 仅支持 macOS M 系列（Apple Silicon / arm64）**：✅ 用户明确要求。
- 理由：单一架构免除 x86_64 兼容矩阵；充分利用 M 系列统一内存架构做**零拷贝路径解析**与 Metal 加速的 Quick Look 缩略图渲染；原生二进制 < 8MB。
- 取舍：放弃 Intel 用户（macOS 存量中占比持续下降，且本工具的用户画像以新设备用户为主）。
- 要求：最低部署目标 macOS 13 (Ventura)，CI 构建 arm64 单架构。

**决策 2 — 存储模型为"路径引用"而非"文件实体"**：✅ 需求 2。
- 挂载时：仅记录 `URL` + `security-scoped bookmark`（跨沙盒持久化）+ 元数据（名称/大小/图标/**来源路径**）。
- 不产生任何文件副本；应用数据目录仅存一个小的 SQLite/JSON 索引（预计 < 1KB/条目）。
- 这是与 Yoink/Dropover 的**本质差异**，也是"大文件秒挂"的来源。

**决策 3 — 拖出执行真实移动（优先支持 Finder）**：✅ 需求 3。
- 拖到 Finder/桌面（文件系统目标）：采用 **NSFilePromiseProvider 机制**——Finder 在目标目录请求写入时，FileTmpShelf 回调中执行 `FileManager.moveItem`，即"承诺交付 = 移动完成"。同卷场景保证源文件真实移动到目标位置。
- 拖到第三方 App（非文件系统目标）：通过 pasteboard 提供 `public.file-url` 引用，该场景源文件保留，drop 后移除货架条目。
- 跨卷：遵循系统复制行为，V2 提供"移动完成后校验删除源文件"。
- **用户面不展示"移动/复制"技术概念**：交互只有自然的拖放；Finder 是 V1 最高优先级验证目标。

**决策 4 — 全局快捷键唤醒**：✅ 需求 4。
- 默认 ⌥X（可自定义），基于 Carbon `RegisterEventHotKey`（全局、低延迟、不依赖辅助功能权限），设置页提供录制 UI。
- 双入口：快捷键 + 菜单栏图标点击。

### 5.2 交互流程（用户旅程）

```
[任意应用] ──⌥X──▶ [FileTmpShelf 浮动面板]
                        │
     拖入（零拷贝）      │ 拖出（真实移动）
   Finder/任意App ──▶ 货架条目 ──▶ Finder / 桌面
                        │
              [源文件移到目标 + 条目移除]
```

### 5.3 UI 构成（初稿）

- **浮动面板**：`NSPanel`，无边框、圆角、半透明（毛玻璃），可拖动，记住上次位置；条目为横向缩略图列表（图标 + 名称 + 大小 + **来源路径** + 失效标记）。
- **菜单栏**：常驻图标，下拉菜单（唤出面板 / 清空货架 / 设置 / 退出）。
- **设置窗口**：快捷键录制、开机启动、面板透明度、外观、清空策略。
- **空状态**：面板无条目时显示引导文案"拖文件到这里，或按 ⌥X 呼出"。

### 5.4 关键设计决策

| # | 决策 | 选择 | 舍弃 | 原因 |
|---|------|------|------|------|
| 1 | 平台 | 原生 SwiftUI | Flutter 跨平台 | M 系性能、系统集成、体积 |
| 2 | 存储 | 路径引用+bookmark | 文件拷贝 | 零拷贝、大文件友好 |
| 3 | 移动语义 | file promise 真实移动（Finder 优先） | 纯 pasteboard 复制 | 满足"拖过去就到位" |
| 4 | 热键 | ⌥X 默认 + Carbon RegisterEventHotKey | NSEvent 全局监听 | 低延迟、免辅助功能权限 |
| 5 | 分发 | 官网 dmg（公证） | App Store | 文件访问更灵活、迭代更快 |
| 6 | 多货架 | V2 再做 | V1 单货架 | 控制首版范围 |

## 6. Technical Considerations（技术考量）

### 6.1 技术栈建议

| 层 | 选型 | 说明 |
|----|------|------|
| 语言 | Swift 5.9+ / SwiftUI | 原生 arm64 |
| 窗口 | NSPanel（无边框浮动置顶） | 面板级 |
| 热键 | Carbon RegisterEventHotKey | 全局、低延迟 |
| 拖放 | NSFilePromiseProvider + NSPasteboard(file-url) | Finder 移动语义优先 |
| 持久化 | SQLite（或 UserDefaults+JSON 兜底） | 货架索引 |
| 沙盒 | 不启用（dmg 分发，非 App Store） | 文件访问更灵活；开启 Hardened Runtime + 公证 |
| 最小系统 | macOS 13+ (Ventura) | M 系列全兼容 |

### 6.2 Dependencies（依赖）

| 依赖 | 用途 | Owner | Timeline risk |
|------|------|-------|---------------|
| 文件访问权限（用户授予的文件夹/文件） | 挂载与移动 | 工程 | Med（需处理 bookmark 失效） |
| 公证流程（Developer ID + notarization） | dmg 分发 | 工程/PM | Low（首次配置一次性） |
| 辅助功能权限（可选，用于读取前台应用） | V2 增强（如拖拽来源识别） | 工程 | Low（V1 不依赖） |

### 6.3 Known Risks（已知风险）

| Risk（风险） | Likelihood（可能性） | Impact（影响） | Mitigation（缓解措施） |
|------|------------|--------|------------|
| security-scoped bookmark 失效（iCloud/外置盘拔出） | Medium | High | 启动时批量解析并标记失效条目；提供"重新定位"入口 |
| 跨卷场景为复制而非移动，用户可能误解 | Medium | Med | V1 遵循系统行为；UI 弱化技术概念；V2 补校验删除 |
| 第三方 App 对 file promise 支持差异 | Medium | Med | 对不支持 promise 的 App 回退为 file-url pasteboard |
| 移动失败导致数据丢失恐惧 | Low | High | 移动成功才移除条目；失败回滚并提示，数据零丢失 |
| 全局热键冲突 | Med | Low | 冲突检测 + 一键重置默认键 |
