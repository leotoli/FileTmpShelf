# S4 手动验收清单 — NSPanel 拖放行为

> 对应 docs/SPIKE.md §6（Spike 4）。核心验证"真实拖拽不抢焦点"依赖 GUI 交互，
> 无法在单元测试中自动化，故以人工验收清单形式固化，供评审会逐项打勾。
>
> 环境：M 系 Mac，macOS 13+（建议同时抽验 14/15），非沙盒 Debug 构建。

## 0. 准备

- [ ] `cd FileTmpShelf && xcodebuild -project FileTmpShelf.xcodeproj -scheme FileTmpShelf -destination "platform=macOS" -derivedDataPath build/DerivedData build` 成功
- [ ] 运行 app，⌥C 唤出面板（或点菜单栏图标），面板出现在主屏右上角
- [ ] 在 Finder 准备测试素材：2 个文本文件、1 个文件夹、1 个大文件（≥1GB，稀疏文件即可）
- [ ] 打开一个"前台对照应用"（推荐 TextEdit 光标置于文本内，确保它持有键盘焦点）

---

## 1. 拖入不激活 FileTmpShelf、不打断前台应用（重点验收项）

对应 SPIKE §6.3 第 1 条。核心配置：`styleMask = [.borderless, .nonactivatingPanel]` +
`becomesKeyOnlyIfNeeded = true`，面板只在内部控件明确请求 key 时才成为 key window。

- [ ] **1.1 前台焦点不丢**：在 TextEdit 中连续打字 → 从 Finder 拖一个文件到面板 → 立即在 TextEdit 继续打字
      —— 字符应仍进入 TextEdit（面板未抢键盘焦点）
- [ ] **1.2 前台应用不被激活/打断**：拖入瞬间观察菜单栏仍显示 TextEdit 菜单、Dock 高亮不变、
      FileTmpShelf 未变成前台 app（accessory 应用本无 Dock 图标，以菜单栏归属为准）
- [ ] **1.3 拖入仍正常挂载**：文件成功出现在面板条目上（说明 nonactivating panel 不影响 drop 命中）
- [ ] **1.4 反复拖入多次**（连续 5 次）：前台应用焦点始终不丢
- [ ] **1.5 前台上处于全屏应用时**（如全屏视频/演示）：唤出面板并拖入，前台全屏应用不被打断、
      `.fullScreenAuxiliary` 保证面板在全屏之上可见可拖

预期：以上全过 → "面板不抢焦点"成立，SPIKE §6.4 决策为**决策确认**。

---

## 2. 拖入/拖出双向正常

- [ ] **2.1 拖入**：Finder → 面板（文件/文件夹均可），条目出现、名称/来源路径正确
- [ ] **2.2 拖出到 Finder**：从面板条目拖出到「Finder 窗口」→ 出现可放置光标，松开后目标位置出现文件副本
- [ ] **2.3 拖出到桌面**：同 2.2，目标为桌面
- [ ] **2.4 拖出到第三方 App**：拖到文本编辑器附件区 / 浏览器上传框（Safari/Chrome）
      —— `public.file-url` 引用应可送达（不接受属第三方限制，记录即可）
- [ ] **2.5 拖出过程中面板保持置顶不消失**（拖拽会话期间面板一直在，无闪烁）
- [ ] **2.6 拖出到 Finder 为复制语义**（源文件仍在原地）—— 与 SPIKE §6.1 假设一致；
      "真实移动"属 S2 的 `NSFilePromiseProvider` 范畴，不在 S4 验收内
- [ ] **2.7 不可达条目**：删除源文件后（或拖入后手动删除源文件）条目变半透明、显示"不可达"，
      尝试拖出时**不发起拖拽**（无拖动跟随）

## 3. 多显示器

前置：`isMovableByWindowBackground = true`，按住面板空白处可整体拖动面板。

- [ ] **3.1 跨屏拖放**：把面板拖到副屏 → 从副屏 Finder 拖文件入面板 → 从面板拖出到副屏 Finder 窗口，
      全程无跳屏/无卡顿
- [ ] **3.2 面板可被拖到任意屏**（利用背景拖动，多显示器移动不受限）
- [ ] **3.3 三屏/排列变更后**：面板位置与显示可见（`canJoinAllSpaces` 全 Space 可见）

---

## 4. 100 条目流畅

- [ ] **4.1 挂载 100 文件**：Finder 中全选 100 个文件一次拖入，条目全部出现，无卡顿
      （观察拖入到条目渲染完成的耗时，参照 S1 的 <1.5s 挂载目标）
- [ ] **4.2 横向滚动**：100 条目下滚动面板货架，帧率正常、无掉帧
- [ ] **4.3 拖出响应**：在 100 条目下连续拖出 5 个条目，每次拖拽会话即时发起、无延迟
- [ ] **4.4 挂载期间面板可交互**：drop 处理用 async/await（无主线程阻塞），拖入后滚动/拖出仍即时响应

---

## 5. 已知边界（记录即可，不阻塞验收）

- [ ] **5.1 首次点击即拖拽**：`.nonactivatingPanel` 下首次鼠标事件是否直达条目视图存在系统差异。
      若面板刚唤出且 app 未激活，第一次"点击并拖拽"条目若未生效，需要先点一下再拖 —— 记录结果，
      若失败需为条目启用 `acceptsFirstMouse`（记入后续开发）
- [ ] **5.2 横向滚动 vs 拖拽判定**：横向 ScrollView 内条目按拖 vs 滚动的位移阈值，记录手感是否可用
- [ ] **5.3 全屏覆盖**：`.fullScreenAuxiliary` 使面板在全屏应用之上可见；若产品不希望覆盖全屏内容，
      去掉该项即可（评审会决策点）
