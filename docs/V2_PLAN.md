## 2. V2-1 默认热键 ⌥C → ⌥X

### 背景与动机

- MVP 默认 ⌥C（`SettingsStore.defaultKeyCode = 8`）。⌥C 在**中文输入法（搜狗/微信/系统拼音）与部分 IDE（VS Code、JetBrains）**中常被占用或用于快捷输入，冲突概率高。
- ⌥X 更冷门，作为全局热键冲突面更小。用户明确要求。

### 改动范围

| 文件 | 改动 |
|------|------|
| `Sources/Core/SettingsStore.swift` | `defaultKeyCode: UInt32 = 8` → **`= 7`**（kVK_ANSI_X = 7）；`defaultModifiers` 保持 `[.option]` |
| `Sources/App/AppEntry.swift` | 菜单栏标题默认文案 `⌥C` → `⌥X`；冲突提示文案同步 |
| `docs/PRD.md` / `README.md` / `docs/FAQ.md` / `docs/V2_PLAN.md` | 快捷键文档全部更新 ⌥C → ⌥X |
| `Tests/SettingsStoreTests.swift` / `Tests/HotKeyManagerTests.swift` | 默认值断言更新（⌥X = keyCode 7） |
| 用户迁移 | 已自定义过快捷键的用户不受影响（UserDefaults 已存值优先） |

### 验收标准

- [ ] 全新安装默认显示 ⌥X，按下 ⌥X 唤出/隐藏面板
- [ ] 设置窗口录制显示 ⌥X，可改回 ⌥C 或其他组合
- [ ] 已有用户自定义快捷键不因升级被重置
- [ ] 文档快捷键全部为 ⌥X
- [ ] 测试全绿

### 决策点（PM 建议）

- **是否提前到 V1**：V1 尚未签名分发（仅 RC 未签名），改默认键成本最低。**建议 V1 就改**，避免"发布后才改默认键"的迁移成本。若确认，V2-1 将从本规划移入 V1 补丁，V2 不再包含。
- ⌥X 在部分终端（iTerm 中 ⌥X 可能映射为特殊字符）有轻微占用风险——实现时做一次真机冲突探测，若冲突则 fallback 提示用户。

## 3. V2-2 副屏唤醒：工作屏幕弹出，位置与主屏一致

### 背景与动机

- MVP 面板位置逻辑：记住**全局绝对坐标**（`UserDefaults panelFrame`），启动/唤醒时若该坐标仍在某屏上则恢复，否则回退主屏右上角。
- 问题：用户在主屏把面板拖到右上角后，切到副屏工作再按快捷键，**面板仍然出现在主屏**——用户得跨屏去找。
- 目标：**唤醒时面板出现在鼠标当前所在屏幕（工作屏幕）的对应位置**；"位置相同"指**相对屏幕的位置一致**（如都是右上角偏移 20pt），而非全局坐标一致。

### 技术方案

**核心：位置模型从"全局绝对坐标"升级为"屏幕相对位置"**

1. **唤醒时确定目标屏幕**：
   - 读鼠标位置 `NSEvent.mouseLocation` → `NSScreen.screens.first { $0.frame.contains(point) }` 得到当前工作屏
   - 若鼠标在多个屏幕的边界（罕见），取距离鼠标最近的屏幕或主屏兜底

2. **位置语义**：
   - 保存面板相对屏幕的**锚点 + 偏移**（如 `.topRight` + `(-20, -40)`），而不是绝对 NSRect
   - 唤醒时：`目标屏.frame + 锚点偏移` → 面板位置
   - 用户拖动面板时，实时把当前绝对位置**反算**为相对锚点存储（拖动结束 `didMoveNotification` 时）

3. **数据兼容**：
   - V1 的 `panelFrame`（绝对坐标）继续读取作为 fallback：若相对锚点不存在（V1 升级用户），先按 V1 逻辑显示，用户拖动一次后自动迁移为新模型
   - 新 key：`panelAnchor`（enum: topLeft/topRight/bottomLeft/bottomRight）+ `panelOffset`（NSSize）

4. **多屏一致性**：
   - 相对锚点在所有屏幕通用 → 主屏右上角、副屏右上角位置**观感一致**（"位置相同"）
   - 不同分辨率屏幕：用"屏幕可见帧的百分比"（如 x=右边缘-5%, y=顶部-12%）而非固定 pt，跨分辨率也一致

### 改动范围

| 文件 | 改动 |
|------|------|
| `Sources/UI/ShelfPanel.swift` | `ShelfPanelController`：`savedFrame` → `savedAnchor+offset`（保留 V1 key 读取 fallback）；`show()` 时按鼠标所在屏计算位置；拖动结束反算锚点 |
| `Sources/Core/SettingsStore.swift` | 新增锚点/偏移持久化 key（或独立 PanelPositionStore） |
| `Tests/ShelfPanelPositionTests.swift`（新建） | 纯逻辑测试：鼠标在屏 A → 面板在屏 A 相对位置；鼠标在屏 B → 屏 B；无鼠标位置 → 主屏兜底；V1 数据迁移 |

### 验收标准

- [ ] 主屏工作按快捷键 → 面板出现在主屏右上角（默认锚点）
- [ ] 切到副屏工作按快捷键 → 面板出现在**副屏**右上角（位置观感与主屏一致）
- [ ] 用户拖动面板到某位置 → 下次唤醒保持该相对位置
- [ ] 显示器拔插/分辨率变化：锚点模型不失效（V1 绝对坐标模型会）
- [ ] V1 升级用户：首次唤醒显示 V1 位置，拖动后迁移到锚点模型
- [ ] 测试全绿

### 决策点（PM 建议）

- **"位置相同"的两种解读**：①相对锚点一致（推荐，跨屏观感一致）②记住每个屏幕的独立绝对位置。若用户更想要②，实现差异不大（`[screenID: NSRect]` 字典），V2 评审时确认。

## 4. V2-3 设置页补充：清除所有货架 + 关于

设置窗口本身（快捷键录制/开机启动/透明度/清空阈值）已在 V1 完成并修复唤起问题，V2 只补充两项：

### 4.1 清除所有货架（🔴 V2 新增设置项）

- **背景**：V1 已有「清空货架」双入口（面板垃圾桶 + 菜单栏，>3 条确认）。V2 在**设置页**增加显式入口，且多货架（V2-4）落地后"清除所有货架"= 清空全部货架的所有条目
- **方案**：设置页新增「清除所有货架」按钮（危险操作样式：红色/警示图标）
  - 点击 → 确认对话框：显示将移除 N 个条目、明确"仅移除引用不删除源文件"
  - 确认后：清空所有货架（V1 单货架 = `ShelfStore.removeAll()`；V2 多货架 = 遍历所有 shelf-<id>.json）
  - 与现有清空共用确认阈值逻辑（≤3 直接清空，>3 确认）
- **验收**：设置页按钮可点；确认后货架为空且源文件完好；多货架场景全部清空

### 4.2 关于 FileTmpShelf（🔴 V2 新增设置项）

- **方案**：设置页新增「关于」分区（或独立 About 视图）：
  - App 名称 + 版本号（读 `Bundle.main` CFBundleShortVersionString）
  - 图标（复用 AppIcon）
  - 版权信息 + GitHub 仓库链接（`https://github.com/leotoli/FileTmpShelf`）
  - 开源许可声明（若转 public + MIT）
  - "检查更新"入口（联动 V2-8 手动更新）
- **验收**：显示版本号；仓库链接可点击跳转；无虚构信息

### 设置页改动范围

| 文件 | 改动 |
|------|------|
| `Sources/App/AppEntry.swift` | SettingsView 增加「清除所有货架」按钮 + 「关于」分区/视图 |
| `Sources/Core/ShelfStore.swift` | `clearAllShelves()`（多货架时遍历；V1 单货架即 removeAll） |
| `Tests/SettingsStoreTests.swift` 等 | 新增清除所有货架/关于信息测试（版本号读取、清除语义） |

## 5. V2-8 手动更新（含提醒 + GitHub Releases）

### 方案

1. **更新检查**：设置页「关于」→「检查更新」按钮（或菜单栏「检查更新…」）
   - 请求 `https://api.github.com/repos/leotoli/FileTmpShelf/releases/latest`（私有仓库需 gh token；公开则匿名可读）
   - 解析 `tag_name` 与本地版本比较（SemVer）
2. **更新提醒**：启动时异步检查（间隔节流，如每天最多 1 次），有新版时菜单栏/通知横幅提醒「发现新版本 vX.Y.Z」
   - 可关闭（设置项「自动检查更新」默认开）
3. **下载安装**：点击提醒/检查结果 → 打开 Releases 页面（浏览器）或直接下载 dmg 到 Downloads 并提示安装
   - 不做自动替换 app（手动安装，降低风险）
4. **网络失败容错**：无网络/API 限流 → 静默失败或提示"检查失败"

### 验收标准

- [ ] 「检查更新」能获取 GitHub Releases 最新版本并正确比较
- [ ] 启动时有新版 → 提醒一次，可关闭
- [ ] 网络失败不崩溃，友好提示
- [ ] 点击更新 → 打开 Releases 页面或触发下载
