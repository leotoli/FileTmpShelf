## 0. V2 定位

MVP 已验证核心价值闭环（⌥C 唤出 → 拖入 → 拖出真实移动 → 清空）。V2 的目标是**扩展场景覆盖 + 打磨多显示器体验**，把"单屏单货架"升级为"多屏随手可用"。

**V2 范围原则**：不改变 V1 已验证的存储模型（路径引用零拷贝）和移动语义（file promise 真实移动）；只在其上叠加多屏、多货架、效率增强。

## 2. V2-1 默认热键 ⌥C → ⌥X

### 背景与动机

- MVP 默认 ⌥C（`SettingsStore.defaultKeyCode = 8`）。⌥C 在**中文输入法（搜狗/微信/系统拼音）与部分 IDE（VS Code、JetBrains）**中常被占用或用于快捷输入，冲突概率高。
- ⌥X 更冷门（X 键位 + option 组合在主流应用中使用较少），作为全局热键冲突面更小。
- 用户明确要求。

### 改动范围

| 文件 | 改动 |
|------|------|
| `Sources/Core/SettingsStore.swift` | `defaultKeyCode: UInt32 = 8` → **`= 7`**（kVK_ANSI_X = 7）；`defaultModifiers` 保持 `[.option]` |
| `Sources/App/AppEntry.swift` | 菜单栏标题默认文案 `⌥C` → `⌥X`；冲突提示文案同步 |
| `docs/PRD.md` / `README.md` / `docs/FAQ.md` | 快捷键文档全部更新 ⌥C → ⌥X |
| `Tests/SettingsStoreTests.swift` / `Tests/HotKeyManagerTests.swift` | 默认值断言更新（⌥X = keyCode 7） |
| 用户迁移 | 已安装 V1 用户若改过快捷键，UserDefaults 里存的是用户自定义值，**不受影响**（只有从未改过的用户读到新默认值） |

### 验收标准

- [ ] 全新安装默认显示 ⌥X，按下 ⌥X 唤出/隐藏面板
- [ ] 设置窗口录制显示 ⌥X，可改回 ⌥C 或其他组合
- [ ] 已有用户自定义快捷键不因升级被重置（UserDefaults 已存在值优先）
- [ ] 文档（README/FAQ/PRD/Release Notes）快捷键全部为 ⌥X
- [ ] 测试全绿

### 决策点（PM 建议）

- **是否提前到 V1 发布前**：若 V1 尚未大规模分发（当前仅 RC 未签名），建议**直接在 V1 就改**，避免"发布后才改默认键"的迁移成本。若 V1 已分发，则 V2 改，并加 Release Notes 醒目提示。
- ⌥X 在部分终端（iTerm 中 ⌥X 可能映射为特殊字符）有轻微占用风险——V2 实现时做一次真机冲突探测（与本机已注册热键比对），若冲突则 fallback 提示用户。

## 3. V2-2 副屏唤醒：工作屏幕弹出，位置与主屏一致

### 背景与动机

- MVP 面板位置逻辑：记住**全局绝对坐标**（`UserDefaults panelFrame`），启动/唤醒时若该坐标仍在某屏上则恢复，否则回退主屏右上角。
- 问题：用户在主屏把面板拖到右上角后，切到副屏工作再按 ⌥X，面板**仍然出现在主屏**——用户得跨屏去找。
- 目标：**⌥X 唤醒时，面板出现在鼠标当前所在屏幕（工作屏幕）的对应位置**；"位置相同"指**相对屏幕的位置一致**（如都是右上角偏移 20pt），而非全局坐标一致。

### 技术方案

**核心：位置模型从"全局绝对坐标"升级为"屏幕相对位置"**

1. **唤醒时确定目标屏幕**：
   - 读鼠标位置 `NSEvent.mouseLocation` → `NSScreen.screens.first { $0.frame.contains(point) }` 得到当前工作屏
   - 若鼠标在多个屏幕的边界（罕见），取 `NSScreen.screens.max { 距离鼠标最近 }` 或主屏兜底

2. **位置语义**：
   - 保存面板相对屏幕的**锚点 + 偏移**（如 `.topRight` + `(-20, -40)`），而不是绝对 NSRect
   - 唤醒时：`目标屏.frame + 锚点偏移` → 面板位置
   - 用户拖动面板时，实时把当前绝对位置**反算**为相对锚点存储（拖动结束 `didMoveNotification` 时）

3. **数据兼容**：
   - V1 的 `panelFrame`（绝对坐标）继续读取作为 fallback：若相对锚点不存在（V1 升级用户），先按 V1 逻辑显示，用户拖动一次后自动迁移为新模型
   - 新 key：`panelAnchor`（enum: topLeft/topRight/bottomLeft/bottomRight）+ `panelOffset`（NSSize）

4. **多屏一致性**：
   - 相对锚点在所有屏幕通用 → 主屏右上角、副屏右上角位置**观感一致**（"位置相同"）
   - 不同分辨率屏幕：锚点+偏移在副屏可能略微偏离视觉位置，V2 用"屏幕可见帧的百分比"（如 x=右边缘-5%, y=顶部-12%）而非固定 pt，跨分辨率也一致

### 改动范围

| 文件 | 改动 |
|------|------|
| `Sources/UI/ShelfPanel.swift` | `ShelfPanelController`：`savedFrame` → `savedAnchor+offset`（保留 V1 key 读取 fallback）；`show()` 时按鼠标所在屏计算位置；拖动结束反算锚点 |
| `Sources/Core/SettingsStore.swift` | 新增锚点/偏移持久化 key（或独立 PanelPositionStore） |
| `Tests/ShelfPanelPositionTests.swift`（新建） | 纯逻辑测试：鼠标在屏 A → 面板在屏 A 相对位置；鼠标在屏 B → 屏 B；无鼠标位置 → 主屏兜底；V1 数据迁移 |

### 验收标准

- [ ] 主屏工作按 ⌥X → 面板出现在主屏右上角（默认锚点）
- [ ] 切到副屏工作按 ⌥X → 面板出现在**副屏**右上角（位置观感与主屏一致）
- [ ] 用户拖动面板到某位置 → 下次唤醒保持该相对位置
- [ ] 显示器拔插/分辨率变化：锚点模型不失效（V1 绝对坐标模型会）
- [ ] V1 升级用户：首次唤醒显示 V1 位置，拖动后迁移到锚点模型
- [ ] 测试全绿

### 决策点（PM 建议）

- **"位置相同"的两种解读**：①相对锚点一致（推荐，跨屏观感一致）②记住每个屏幕的独立绝对位置（用户把主屏面板拖到副屏特定位置后，副屏唤醒也出现在那里）。如果用户更想要②（每个屏独立记忆），实现差异不大（`[screenID: NSRect]` 字典），V2 评审时确认。
- 是否需要"唤出时鼠标跟随"（面板出现在鼠标旁，类似菜单）？——不是本次需求，列入 V2.5 评估。

## 4. V2 其余需求简案（沿用 PRD 路线图）

### V2-3 多货架（P1）
- 货架列表（侧栏或菜单），每货架独立命名 + 独立存储文件（`shelf-<id>.json`）
- 快捷键循环切换货架（可选 ⌥X 长按/双击）
- 面板 UI：货架切换 Tab 或下拉

### V2-4 跨卷真实移动（P1）
- 移动完成后校验目标存在 + 源删除（`moveItem` 跨卷会复制，成功后删除源）
- 失败回滚（目标复制失败则不删源），进度提示（大文件）

### V2-5 多选/排序（P1）
- ⌘ 点击多选 → 批量拖出/清空
- 拖拽排序条目；置顶（固定常用文件）

### V2-6 Quick Look 预览（P2）
- 空格在条目上触发 `QLPreviewPanel`（需 NSResponder 链支持）

### V2-7 统计面板（P2）
- 记录每次移动的文件数/大小/节省拷贝量；面板/菜单显示周/月统计

### V2-8 Sparkle 自动更新（P2）
- 需先完成签名公证（V2 前置条件）；`SUFeedURL` 指向 GitHub Releases 或自托管 feed
